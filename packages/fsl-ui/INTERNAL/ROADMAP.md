## Program — route to v1

### North star

`fsl-theme` + `fsl-ui` finished to the level where they are the default
choice over Tailwind/Chakra/Material for ttoss applications: semantic,
accessible, AI-first, and visually refined out of the box. **Finished means
in production use — not feature-complete on paper.**

### Scope ruling (2026-07-22)

The program is two packages and one docs section. Everything else is support
tooling, admitted only when it serves the adoption gate.

### The gate (replaces D1 → D2; revised 2026-07-22)

**fsl-ui v1.0 ships when Studio v2 is deployed with its four blocks and the
friction log is worked down to zero blockers.** The blocks (Login,
Settings/CRUD, Dashboard, Pricing) are real application flows in miniature —
they exercise forms+validation, tables+selects, dataviz, and marketing
composition, which is the friction a business app would generate. The
residual self-reference (the system's own showcase validating the system) is
accepted and named: **"first screen in an external business app" is the v1.x
milestone that follows**, not a v1.0 blocker. The AI-executability benchmark
(D1) stays demoted to optional evidence. Rationale: a gate the team never
runs blocks forever; the Studio gate is reachable, in-repo, and generates
representative friction.

## Before deciding anything — read the authorities first (binding)

Added 2026-07-29 because it was earned the hard way. Three "owner decisions"
were escalated during forms C, and reading the design documentation afterwards
showed that **two of the three were already decided in writing** and the theme
already carried the tokens. One friction entry (F-032) was filed claiming a token
was missing that exists. The failure was not analysis — it was not looking.

**The rule: a question about colour, geometry, responsiveness or token grammar is
answered by the design docs before it is reasoned about, and certainly before it
is escalated.** If the docs and a measurement disagree, that is a finding worth
writing down — but the docs are the starting position, not the fallback.

`model.md` §11 already fixes the order when artefacts disagree, and it applies
here too: **FSL Lexicon / Structural Language** (identity and vocabulary) →
**`Types.ts`** (what exists and in what shape) → **family docs** (how to pick in a
real case). Identity beats enforcement beats guidance when the argument is about
meaning; enforcement beats guidance when it is about what exists.

### Two traps this list exists to prevent

- **"The theme lacks a token for X."** Check the theme before filing it. `input.negative.text.default` (`red.700` light / `red.300` dark) exists and is unread; F-032 was filed as a missing token and was really a component reading the wrong role.
- **"The contrast suite will catch it."** It will not, in one direction. `extractTextBackgroundPairs` and `extractBorderBackgroundPairs` both iterate over what exists and `continue` when the counterpart is absent — so **removing** a background silently drops its pairs and the suite stays green. Any change that deletes a colour token owes an explicit replacement assertion.

### A-P0: bugs and broken promises

- **A1. ProgressBar indeterminate animation was dead** — the `@keyframes` was defined nowhere. → `src/tokens/keyframes.ts` (`ANIMATION_NAMES` registry + idempotent, SSR-safe injection with a `prefers-reduced-motion` kill switch) and **contract invariant #8**: every `animation:` in `src/` must reference a registered name that has a `@keyframes` block.
- **A2. Dialog width was unconfigurable** — a hardcoded `maxWidth` the documented wrapper workaround could not reach. → `--fsl-dialog-max-width` / `--fsl-dialog-max-height` knobs with the previous literals as fallbacks (ADR-002, CONTRACT §7).
- **A3. Seven hardcoded English defaults** → **ADR-001**, the package's copy doctrine: components never depend on `@ttoss/react-i18n`, all user-facing text is caller-supplied, and defaults are **forbidden** for flow-critical labels — enforced by type (`ConfirmationDialog`'s `armedLabel` is required-iff-destructive through a discriminated union on `consequence`; `WizardNavigation`'s labels are required unless the render prop owns the row). `Select`'s placeholder and the Wizard's `announceStep` copy stay documented English fallbacks with override props. CONTRIBUTING §6.
- **A4. npm packaging broke the AI-first promise** — `files: ["dist"]` shipped no CONTRACT, no `llms.txt`, and a README citing `src/…` paths absent from the tarball. → `files: ["dist", "llms.txt", "src/tokens/CONTRACT.md"]`, `llms.txt` authored as the machine-readable ground truth (semantic model, catalog, Entity→token map, state cascade, integration rules), README rewritten to a quickstart valid in the published artifact.
- **A5. Stale references and old identity** — `ISSUE.md` citations to a nonexistent file, `@ttoss/ui2`/`@ttoss/theme2` naming, a phantom `totalSteps` prop. → all repointed/renamed; the phantom prop survived because jest runs babel without type-checking, so **`tsc` (build/CI) is the type gate**, not the test run.

### A-P1: real-world API & robustness

- **A6. Escape-hatch policy (the systemic decision that unblocked A2 and the B waves)** → **ADR-002**: composite-scoped CSS custom properties (`--fsl-<scope>-<knob>`, consumed with the current literal as a fallback) are the **single** official escape hatch, preserving the no-visual-props doctrine. `src/tokens/escapeHatch.ts` (`fslVar`) is the one consumption path; contract tests ban raw or fallback-less `var(--fsl-…)` and any CSS var outside the `--tt-`/`--fsl-` namespaces. CONTRACT §7 carries the policy plus the registered-knob table.
- **A7. AccordionTrigger swallowed the Button API** (disabled styling was unreachable dead state) → props extend RAC `ButtonProps` minus `style`/`className`/`slot`, plus `headingLevel` (default 3).
- **A8. RTL correctness** — `Switch` positioned its thumb with physical `left:`. → logical properties throughout, and a **contract invariant banning physical box properties** across `src/`, so the class cannot return.
- **A9. Toast rode RAC `UNSTABLE_` APIs on an open range** → **ADR-003**: pinned `~1.19.0` (the minor the package actually ran against — pinning the audit's literal `~1.9.0` would have been a silent downgrade breaking ToastRegion) plus a canary test importing every consumed `UNSTABLE_` symbol with an upgrade note.
- **A10. Tree-shaking was unproven** → `scripts/verify-treeshake.mjs` (esbuild, prefers `dist`): a Button-only bundle is **1 812 bytes** minified against a 16 000 budget, zero composite leakage, and the README states the number. **Follow-up (2026-07-16, ADR-006):** once `dist` was locally buildable the probe showed the default single-chunk build did **not** shake — a Button-only import dragged 61 KB of composites — fixed by `unbundle: true` in `tsdown.config.ts`, so the guarantee holds for the published artifact.
- **A11. `@ttoss/forms` (RHF + Zod) bridge** → **ADR-004**: a documented recipe living as an integration test, no adapter entry. `formsBridge.test.tsx` wires TextField + Select + Checkbox through `Controller`/`useForm`/`zodResolver`; `@ttoss/forms` stayed a devDependency and its source untouched. **Superseded 2026-08-02 by ADR-027** (the recipe names its upstreams directly; fsl-ui takes no form-library dependency).

### A-P3: accessibility & test hardening

- **A12. Wizard focus management + announcements** — step changes moved no focus and announced nothing. → focus moves to the new step/summary body on change (never on mount), a visually-hidden `aria-live="polite"` region announces progress, `announceStep` overrides the English fallback per ADR-001; five behaviour tests including a pt-BR localization case.
- **A13. a11y + keyboard test layer** — everything was `fireEvent.click`, no ARIA assertions, no axe. → `DOM_FIXTURES` extracted to `domFixtures.tsx` so a new component's fixture feeds both the contract and axe suites automatically; `a11y.test.tsx` runs jest-axe over every canonical render; `keyboard.test.tsx` (user-event) covers Menu, Dialog, Select and Accordion.
- **A14. Layout-literal rule** — CONTRACT banned colour literals and was silent on layout. → **CONTRIBUTING §4**: a layout literal is allowed only as a named module-level constant with a justification comment (the `TRACK_W` pattern); magic inline literals are forbidden. Existing literals in Menu/Dialog/ProgressBar/Toast converted.

### A-P4: documentation (docs/website)

- **A15. `docs/design/ui-components/index.md` was an "under construction" stub** every "see the React implementation" link landed on. → written: what fsl-ui is, the catalog by Entity, the customization model (§7 knobs + data-attributes), links to component-model and design-tokens — no content duplication, per the repo docs rule.
- **A16. CONTRIBUTING §2.3 example diverged from the code** (the example spread `{...props}` after the identity attributes, so a caller could override `data-composition`) → example fixed with the rationale in a comment, and the aspirational sibling-selector comment in `Accordion.tsx` replaced with a description of the actual divider behaviour.

### B1. Icon story (pre-requisite) `M`

> **Status: ✅ DONE (2026-07-15) — ADR-005: Iconify is the official glyph
> provider**, no hand-authored SVG. An internal semantic layer
> (`src/components/Icon/`) implements `icon-system.md`'s intent contract
> (`icon.{family}.{intent}`): a provider-agnostic vocabulary, a default
> **Lucide** mapping registered offline via `addIcon` behind an idempotent
> `ensureIconGlyphs()` (SSR-safe, no runtime API fetch), and `Icon.tsx` as
> Entity=Structure sized by `vars.sizing.icon.*`. It shipped **internal** and
> became a public export later under ADR-010. The four v0 unicode consumers
> (Accordion, Checkbox, Select, Toast) were retrofitted. Documented in
> CONTRACT §9 + llms.txt.

> clean — Icon fits Entity=Structure with the existing `icon` structural role,
> so no `STRUCTURAL_ROLES` addition and no governance proposal. One real defect
> surfaced and was fixed: on a custom element (`<iconify-icon>`), React renders
> `aria-hidden={true}` as an empty attribute, which does **not** hide from AT —
> the value must be the string `"true"`.
