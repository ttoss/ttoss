# Agentic Workflow

A project's agentic workflow is its instance of this workflow: the [Delivery Process](process.md) with the project's answers to the [parameters](parameters.md) and its [routines](routines.md). Agents read those pages and the project's parameters file; the project's people read one page, `AGENTIC_WORKFLOW.md` at the root of its repository, which [`flow-setup`](https://github.com/ttoss/skills/blob/main/skills/flow-setup/SKILL.md) writes as its final output.

The page shows who acts at each stage in the project, what fires each run, which routines run and when, and where each piece lives, with a person's steps drawn apart from an agent's. `flow-setup` rebuilds it whole from the parameters on every setup and audit, and it is never edited by hand: it holds pointers and no rule, so a change to it is a change to the parameters or the files they point to, followed by `/flow-setup audit`. No entry file names it, so no agent session loads it.

## Template

```markdown
# Agentic workflow — <project name>

> Generated by `/flow-setup` from `<parameters file>` on <date>. Do not edit: change the parameters or the rules they point to, then run `/flow-setup audit`.

Work lives in the Flow project `<proj id>`, under the standing decision [`<task id>`](https://flow.ttoss.dev/app/tasks/<task id>); <the code host> holds the code and its changes. It runs the ttoss [Engineering Workflow](https://ttoss.dev/docs/engineering/workflow): every run reads a task's state from Flow, acts and writes it back, so the next run starts from the graph.
```
